# 裝備評分策略

## 直接執行：依序最佳化所有角色

使用者直接輸入 `/skill:bears-equipment-strategy`（可附帶權重或「依職業安排」等引數）時，視為一個有明確界線的批次配裝要求。這次呼叫明確授權：

- 查詢 `/chars`，以即時回覆確認角色數、顯示順序及原本操作中的角色。
- 最多處理 9 名既有角色；有多名角色時，依 `/chars` 顯示順序使用已觀察到的 `/switch 名稱` 逐一切換。
- 為每名角色套用本 skill 選出的固定權重，並以 `/equip` 套用通過完整檢查的嚴格提升裝備。
- 批次結束後切回原本角色；若只有一名角色，直接處理且不切換。

這項授權不包含 `/autoequip`、建立／刪除／進階角色、購買、販售、銷毀、交易、公開聊天、PvP 或啟動掛機。若角色正在掛機，為取得可用的配裝快照可停止並結算該角色的掛機，但完成後不得自行重新啟動；最終回報哪些角色因此停止掛機。只有切換被遊戲明確以戰鬥中阻擋時，才可嘗試一次 `/flee`，確認脫離後再切換。

若使用者只在一般文字中詢問權重或策略，而不是要求配裝或直接執行此 skill，仍只提供策略，不改變遊戲狀態。

### 批次流程

1. 讀取[遊玩流程](../playing-bear-of-bears/SKILL.md)及[指令參考](../playing-bear-of-bears/commands.md)，再讀取 `bears_history`。後續 Telegram 工具必須逐一執行；每次 `bears_send`／`bears_click` 前重新讀取 history，並先檢查上一個結果。
2. 傳送 `/chars`，只採用本次新回覆中的總數、順序、角色名稱及目前角色標記；[角色文件](../../docs/CHARS.md)僅供核對命名限制，不得取代即時清單。
3. 依清單順序處理每名角色。不是目前角色時才切換；每次切換後必須以新回覆確認角色名稱，並將前一角色的狀態、背包、物品編號與評分結果全部視為失效。
4. 對目前角色先取得新的 `/status`。若狀態確認正在掛機，停止並確認結算後再重新取得 `/status`；接著取得 `/inventory`。只有職業 profile 需要更多證據時才補查 `/skills`。依下節規則決定該角色的固定權重，再呼叫 `bears_optimize_equipment`。
5. 依遊玩流程的完整性、資格、被動／技能、平手及不明結果規則，每次只裝備一件嚴格提升的物品。每次 `/equip` 後重新取得背包、確認穿戴結果並重算，直到沒有可套用的嚴格提升、該角色遇到 blocker，或達到單一角色上限。
6. 可確認目前角色且切換安全時，批次結束或提前停止後切回原本角色；切回後以遊戲回覆確認。操作結果不明時先讀 history，不重送不明操作，也不為了恢復角色而猜測目前狀態。

直接執行本 skill 是最多 9 名角色的明確批次範圍，因此遊玩流程的單次配裝額度分別套用到每名角色，不以一般未限定請求的全域 10 次狀態變更上限截斷整批。每名角色仍最多 6 次 equip 嘗試、10 次狀態變更、40 次查詢及 5 分鐘；切換、必要的 `/stopidle` 與 `/flee` 都計入該角色狀態變更。達到任一上限就停止該角色並繼續下一名；Telegram 速率限制、死亡、角色身分不明或切換結果不明則停止整批。

角色自己的背包不完整、裝備資格不足或未涵蓋的效果取捨，只阻擋該角色；記錄原因後可繼續下一名。不得跨角色共用快照或物品編號，也不得為了完成整批降低完整性標準。最後逐一回報角色、權重、已確認換裝、略過／blocker、掛機變化及是否已回到原角色。

## 選擇權重

權重順序固定為 `ATK／DEF／INT／AGI`，分數為四項裝備屬性與各自權重的乘積總和。
未指定策略時使用 `1／1／1／1`，不要求使用者先理解或填寫數值。
這只代表屬性加總，不代表職業最佳、實戰勝率或 EXP／分鐘最佳。

依下列優先序選擇一次，單次配裝任務內保持固定，不為了讓候選勝出而調整權重：

1. 使用者明確指定四項數值或等權重時，遵守指定，不以職業 profile 覆蓋。
2. 使用者要求「依職業安排」時，根據新觀測的角色職業、主要技能說明與實際戰鬥方式，選擇下表符合證據的 profile；不要求使用者自行填數值。
3. 證據不足、互相矛盾、混合流派或沒有符合的 profile 時，使用等權重並說明缺漏，不猜測未記載的公式。

自訂權重必須完整提供四項有限數值；缺項、NaN 或 Infinity 不可默默補值，先要求修正。
若使用者尚未要求依職業調整，可提出 profile 建議，但本次仍使用預設或已指定的權重。

## 職業 profile

以下是策略起點，不是遊戲官方係數或經實測求得的最適比例。
`2` 表示策略上將該屬性的一點視為其他屬性一點的兩倍價值，不表示傷害倍率。
所有次要屬性仍保留權重 `1`，不宣稱它們對該職業無用。

| 角色／戰鬥方式 | 選用所需證據 | ATK／DEF／INT／AGI |
| --- | --- | --- |
| 未指定、未知職業或證據不足 | 無額外前提；通用回退 | `1／1／1／1` |
| 戰熊或轉職角色，以 ATK 輸出為主 | 當前技能說明或控制條件的實測支持主要輸出依賴 ATK | `2／1／1／1` |
| 法熊或轉職角色，以 INT 輸出為主 | 當前技能說明或控制條件的實測支持主要輸出依賴 INT | `1／1／2／1` |
| 道熊，以 INT 技能為主 | 已確認主要使用的技能依賴 INT；不能只憑「道熊」名稱推定召喚／治療公式 | `1／1／2／1` |
| 道熊，以 ATK 輸出為主 | 已確認主要輸出依賴 ATK，而非只看武器名稱 | `2／1／1／1` |
| 任一職業，明確以承傷為優先 | 使用者指定防禦優先，且已確認 DEF 對目標傷害有作用 | `1／2／1／1` |
| 任一職業，明確以 AGI 效果為優先 | 使用者指定敏捷優先，且當前說明已確認所追求效果依賴 AGI | `1／1／1／2` |

同時符合多個主屬性或目標而無明確優先序時回退等權重，列出衝突，不任意混合 profile。
角色轉職、技能或目標改變時停止沿用舊策略，重新評估；不得為了測試或操弄權重切換角色。直接執行本 skill 時，依批次流程切換既有角色是為了逐一配裝，不屬於權重測試。
單次戰鬥傷害、裝備名稱、稀有度、玩家說法或 `/autoequip` 結果，都不能單獨證明屬性公式。

## 取得證據與交付

需要遊戲查詢或套用裝備時，先讀取 [遊玩流程](../playing-bear-of-bears/SKILL.md) 及其中的指令參考，沿用既有工具與授權界線。
先讀 `bears_history`，再依實際觀測到的指令查詢必要角色／技能資訊；不為了選權重額外發動戰鬥、購買或消耗物品。
只要求策略不代表授權換裝；只有直接執行本 skill 或使用者另行明確要求套用配裝時，才依上述流程換裝。本 skill 不執行背景換裝或啟動掛機。
資料不足時最多補查三次，仍不足就回退等權重，不持續搜尋；補查計入配裝任務既有的查詢與時間上限，不另開額度。

交付實際四項權重、策略來源（使用者指定／通用預設／職業啟發式）、適用的角色與戰鬥方式，以及支持 profile 的 message ID／revision 和觀測時間。
沒有足夠證據時明列回退原因，不把歷史紀錄當成目前角色狀態。
將四項權重明確交給可用的評分工具；工具尚未載入或實作時僅回報策略，不假裝已取得推薦或完成換裝。

評分不得取代裝備資格與完整性檢查：未知部位、實際屬性、目前穿戴或持有狀態時先補查，不補零。
平手保留目前裝備，不因負分自行卸裝；分數提高也不代表一定適合替換。
技能、被動、套裝、MP／HP 等公式未涵蓋因素必須另外揭露；未獲准忽略相關取捨前，阻擋涉及該差異的換裝。
回報完成策略選擇後，只有直接執行本 skill 的批次授權或其他既有授權涵蓋換裝時，才交由遊玩流程繼續逐件確認。
